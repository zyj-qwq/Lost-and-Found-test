# 02 · 项目结构与每个文件的作用

> 把整个项目当成一家餐厅：`backend` 是后厨（做菜、存食材），`frontend` 是前厅（点餐、摆盘），`docs` 是员工手册。前后端通过"接口（API）"传菜。

```
Lost and Found/
├── backend/      后端（Node.js + Express）—— 端口 8080
│   ├── src/
│   │   ├── index.js    服务器主文件：所有接口都在这里
│   │   └── db.js       "数据库"：数据存在 data/db.json 文件里
│   ├── data/db.json    ← 全部的用户/信息/申请数据（可删，删了重置系统）
│   ├── uploads/        ← 用户上传的图片
│   └── package.json    后端依赖清单（express、jwt 等）
│
├── frontend/     前端（Vue 3 + TypeScript）—— 端口 5173
│   ├── index.html      整个网站唯一的 HTML（单页应用）
│   ├── vite.config.ts  开发服务器配置（@ 别名、/api 代理转发）
│   ├── tsconfig.json   TypeScript 配置
│   ├── package.json    前端依赖清单（vue、element-plus 等）
│   └── src/            ★ 所有代码都在这里 ★
│       ├── main.ts         入口：创建应用、装插件、挂载到 #app
│       ├── App.vue         外壳：顶部导航栏 + <router-view> 内容区
│       ├── router/         路由表：网址 → 页面 的对应关系 + 登录守卫
│       ├── stores/         Pinia 全局状态：登录信息（token、用户角色）
│       ├── api/            封装 axios：自动带 token、统一错误提示
│       ├── types/          TypeScript 类型定义（和后端 API.md 对应）
│       ├── utils/          小工具：时间格式化、状态文案映射
│       └── views/          ★ 所有页面 ★（见下表）
│
├── docs/         说明文档（你现在看的）
└── API.md        接口文档：前后端约定的"合同"
```

## 前端一次请求的完整旅程

以"首页加载信息列表"为例：

```
① 浏览器打开 / 首页
      ↓ 路由表查到 "/" → HomeView.vue
② HomeView 的 onMounted 自动执行 fetchList()
      ↓ 调用 src/api/index.ts 的 get('/items', params)
③ axios 请求拦截器：自动从 localStorage 取 token 塞进请求头
      ↓ 请求发往 /api/v1/items
④ Vite 开发服务器发现是 /api 开头 → 转发给 http://localhost:8080
      ↓（vite.config.ts 里配置的代理，解决跨域问题）
⑤ 后端 index.js 匹配 app.get('/api/v1/items', ...) 执行
      ↓ 查 db.json 里的数据 → 筛选/排序/分页 → 返回 { code:0, data:{...} }
⑥ 响应拦截器：code===0 → 直接剥出 data 返回
      ↓
⑦ fetchList 把结果存进 list.value
      ↓
⑧ 模板里的 v-for 因为 list 变了自动重新渲染 → 用户看到列表
```

**如果第⑥步返回 code=10002**（token 失效）：拦截器清掉本地存储 → 通知 auth store 清空内存 → 弹提示 → 跳转登录页。这就是为什么 token 失效会被立刻踢回登录页。

## 几个"魔法目录/文件"的说明

| 名字              | 是什么                   | 需要管理吗                        |
| --------------- | --------------------- | ---------------------------- |
| `node_modules/` | 依赖包的安装结果（300MB+）      | ❌ 不上传不复制，`npm install` 可重新生成 |
| `dist/`         | `npm run build` 的打包产物 | ❌ 构建即可重新生成                   |
| `data/db.json`  | 后端的所有数据               | 想重置系统就删掉它再重启后端               |
| `package.json`  | 依赖清单 + 启动命令           | ✅ 重要，是项目的"身份证"               |

## 常用命令

```bash
# ---- 启动（每天开机后要先启动这两个）----
cd backend  && node src/index.js   # 后端，端口 8080
cd frontend && npx vite            # 前端，端口 5173

# ---- 依赖重装（换电脑/删了 node_modules 之后）----
cd backend  && npm install --registry=https://registry.npmmirror.com
cd frontend && npm install --registry=https://registry.npmmirror.com

# ---- 类型检查 / 打包 ----
cd frontend
npx vue-tsc --noEmit   # 检查类型错误
npx vite build         # 打包生产版本到 dist/
```

> 注意：npm 官方源在国内连不上，装依赖**必须**加 `--registry=https://registry.npmmirror.com`。
